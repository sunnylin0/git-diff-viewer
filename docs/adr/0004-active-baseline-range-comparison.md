# 4. 左側清單作用中基準節點與 100 筆範圍比對模型

Date: 2026-10-27

## Status
Accepted

## Context
使用者需要在左側歷史列表中迅速鎖定一個基準節點（Baseline），並觀察該基準節點之後連續 100 筆提交相對於該基準的累積變更（1 對 N 固定基準比對），而不影響或替換右側已手動挑選的自訂鏈式比對清單。

## Decision
1. **控制入口**：
   - 在左側每個提交卡片的「加入/移除」按鈕後方新增「基準」按鈕（`<button data-action="set-base">基準</button>`）。
2. **狀態與交互行為**：
   - 點擊卡片的「基準」按鈕：將該 commit 設為 **Active Baseline**（琥珀金黃專屬高亮）。
   - 再次點擊同一個已是基準的卡片：**取消基準**狀態，清除所有比對標記恢復預設暗灰色。
   - 點擊其他卡片的「基準」按鈕：切換至新的 Active Baseline，重新計算後續 100 筆。
3. **範圍比對群組（Baseline Range Comparison）**：
   - 自動將該基準後續的 100 個提交節點標記為範圍比對群組。
   - 視覺樣式：100 張卡片統一呈現專屬冷紫色調（高亮邊框與標記）。
   - 資訊呈現：在原有卡片資訊後方額外附加醒目標籤「vs 基準: X(files), Y(+), Z(-)」，以非同步並行/漸進式請求 `git diff <base> <target>` 填入，不阻塞主線程。
4. **面板獨立性**：
   - 此操作完全在左側面板完成，右側比對面板與鏈式比對狀態維持不動。

## Consequences
- 優點：可在左側巨量提交中立即定位基準，並一覽未來 100 個節點的累積變動幅度，且與右側精選清單完全解耦。
- 代價：瞬間可能需要計算最多 100 筆 diff；需透過快取與非同步批次/漸進機制確保 UI 不卡頓。
